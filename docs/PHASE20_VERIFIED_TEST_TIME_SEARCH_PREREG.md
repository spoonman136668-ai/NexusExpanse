## Tasks and training

- Build arithmetic tasks from positive operands 1–12 and `+`, `-`, `*`, `%`, and `//`. For `+` and `*`, use only operands in ascending order, including ties. The raw record is `a<op>b=<answer>` followed by newline. Shuffle each operation's tasks using `random.Random(seed)`, reserving the first two for CHECK and the next one for calibration. Train on the remainder. Evaluation takes the prompt through `=` and checks the exact bounded integer on the first line.
- Build Python tasks from three families with constants 1–12. Each asks for addition, multiplication, or a remainder by the supplied constant, with the plain `def f(x):` signature after a comment. Keep two held constants and one calibration constant per family using the same seeded RNG, and train on the remainder. Each candidate must match six exact test expectations with inputs `-13, -3, 0, 2, 5, 17`. The reference continuation is a single arithmetic `return` expression. The solver never receives the cases or reference answer in its byte prompt. These tests check the listed values and do not formally prove equivalent behavior on every input.
- Each seed has 10 arithmetic and six Python CHECK tasks. Require disjoint exact task prompts across FIT, calibration, and CHECK. The splits share task templates, Python syntax, and operators. This is a held-instance study on synthetic tasks. It does not impose text-window disjointness or test transfer to new operation families. Shuffle FIT records with the same RNG and pad the final block with zero to 63 newline bytes so its length is 1 modulo 64. Validate export on the separate calibration records. ## Search and controls

Candidates 1–15 use nucleus sampling with temperature 0.7, `top_p=0.9`, and seeds `1000 × training_seed + 64 × task_index + candidate_index`, with zero-based indices. Both arms use those same seeds. Every candidate starts from an independently restored frozen INT8 snapshot with always-wake enabled, without updates from the task verifier or from other candidates. Forecasts use only the prompt and bytes already emitted in that candidate. The optional Engram uses the same observed suffix as ordinary generation.
