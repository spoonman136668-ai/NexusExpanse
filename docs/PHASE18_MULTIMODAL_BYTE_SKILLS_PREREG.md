# Phase 18 multimodal byte skills preregistration

This is an offline CPU development experiment frozen before scoring. It tests whether native byte receivers trained on separate domains can route a switched stream and incorporate a fifth domain. It uses repository prose and Python and synthetic audio, image, and telemetry codecs. Conclusions are limited to these distributions, model sizes, training budgets, and five seeds.

## Inputs and training

- Base `90ba28f1eb4268a66b535b24ef5736b2ac79441d`. Run seeds `3201` through `3205` in order. The harness requires a clean checkout of the direct preregistration commit and a fresh external receipt path. It records the commit, tree, and preregistration digest before scoring.
- Prose and code use the same frozen source and file layout as the Phase 9 harness. Take the first 6,081 FIT, 384 CAL, and 1,536 CHECK bytes per domain. If any partition overlaps at 32 bytes, choose the first passing candidate in `seed + 10000 × attempt` for attempts 0 through 7 and record rejections. This check uses only bytes. Exhausting candidates invalidates the run.
- Audio has a pitch marker `0xF0..0xFF` and 64 sample bytes using μ-law companding with μ=255 and levels `0..239`. Image has a marker `0xE0..0xEF` and 64 row-major grayscale bytes with correlated gradients. The audio decode reconstructs quantized sample values. Image decode preserves exact pixels. Use independent seed namespaces for FIT, CAL, and CHECK. Generate 96, 6, and 24 frames respectively, rejecting 32-byte window overlaps with earlier splits before clipping to the same budgets as prose and code. Clipping may leave a partial final record.
- Telemetry uses seven-byte records with a type marker `0xD0..0xD7`, a positive little-endian 16-bit counter delta, three correlated byte channels, and a modulo-256 checksum. Generate one 80-packet encounter and a 48-packet CHECK stream with independent namespaces and no shared 32-byte windows. Telemetry is absent from all resident FIT and CAL data. All streams use the same 256 raw byte IDs and head.
- Verify the 32-byte separation of FIT, CAL, and CHECK for each resident and of encounter and CHECK for telemetry. Verify again across concatenated joins in the monolith's FIT and CHECK streams. Record lengths and SHA-256 digests of all source splits.
- Train one resident each for `prose`, `code`, `audio`, and `image` using CLI `train --train-file ... --eval-file ... --device cpu --dtype fp32 --skill-backbone --use-sdpa --dim 128 --layers 4 --context 64 --epochs 1 --steps-per-epoch 64 --batch-per-domain 1 --eval-blocks 4 --snapshot-quant int8`. Every resident sees 4,096 target bytes in 64 AdamW updates. The same-sized monolith uses the concatenated FIT corpus in that domain order, clipped to a whole-block boundary plus the initial byte. It gets 16,384 target bytes and 256 updates, equal to the total resident budget. The same model seed applies within a run. CHECK readouts do not select parameters. Store INT8 archives and restore their dequantized FP32 neural receivers for scoring.

## Scored comparisons

- Concatenate six 128-byte CHECK segments in order `prose → audio → image → code → audio → prose`. Take the next unused CHECK segment on a repeat. Score the mean negative log probability in bits per byte (BPB) over all 768 bytes. HMM state starts once. Each forecast uses the preceding bytes, and the router updates mixture weights after observing the scored byte. The archived stream cursor and online adaptation state do not participate. The resident weights stay fixed.
- Compare Sticky-HMM BMA with a uniform mixture of the four residents, the lowest BPB of all four single residents and the monolith, and an oracle that selects by ground-truth modality. Oracle BPB is a labeled reference. The route receives no modality labels or switch points. Report dominant-weight routing accuracy on all bytes and on bytes offset 16 and later within each segment, including per-modality settled accuracy.
- Calibrate novelty once from the first 160 CAL bytes per resident using the resident-specific 90th percentile of 64-byte rolling surprise plus 0.5 BPB. Check false novelty on each resident's first 128 CHECK bytes separately. In a continuous stream with 128 prose CAL bytes, the 560-byte telemetry encounter, and 128 audio CAL bytes, probe after byte 96 and every 32 bytes thereafter using at most 192 observed bytes. Trigger only when all residents cross their thresholds. The first trigger receives the fixed registry name `telemetry` and no information about where the domain began. Stop at that trigger. A trigger outside the encounter or no trigger counts as a birth failure.
- On detection run one episodic birth from a cloned resident with 64 isolated updates and suffix memory built from the same observed window. Repack the new neural component as INT8 before registration. No gradients flow through the resident models or mixture. Compare pre/post BPB and routing on each domain's first 128 CHECK bytes in independent streams. A fresh process restores both banks, computes the same held results, and hashes the full forecasts and weights. Report per-domain post-birth routing accuracy after the same 16-byte warm-up. Positive retention drift means a BPB regression.

## Decision rules

**Engineering.** Require zero shared FIT/CHECK 32-byte windows, exact `0.0` causal prefix differences on the first 64 CHECK bytes of all five domains using suffix replacement and truncation, and zero donor forwards. All four resident INT8 snapshots and the monolith must show at least 3.0× size reduction versus FP32 re-export and exact cold state, four parity checks, and probability round trip relative to the exported state. The before/after banks must restore bit-exact forecasts in a fresh process, and resident state and component forecasts must remain exact after the birth probe. A completed birth also stores the new INT8 neural archive in that cold comparison. Require the matched update and byte budgets above, final bare `pytest -q` with zero failures, skips, and warnings, and the legacy prefix benchmark at `0/100` failures. Export compression measures individual archives. Record whole-bank bytes separately with no assumed bank-size advantage over a monolith.

**Scientific DEV.** The routing arm passes only if HMM BPB is strictly lower than both the uniform and best-single reference and settled routing accuracy is at least 80% in each of five seeds. The birth arm passes only if each seed triggers during telemetry, has zero false flags across the four resident CHECK probes, improves held telemetry BPB, preserves resident BPB within +0.05 maximum drift, stores the new neural state in INT8, and achieves at least 80% settled cold routing accuracy on every domain. A seed with no birth fails that arm and still contributes its pre/post bank results. Both arms must pass for DEV PASS. Exactly one passing arm yields MIXED. Neither passing yields FAIL. A failed scored engineering check makes the scientific score INVALID. Report all results and stop after the frozen run. Independent scientific qualification, external media, model scaling, and production deployment are outside this experiment.
