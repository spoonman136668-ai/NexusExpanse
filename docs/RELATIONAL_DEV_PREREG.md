# Compositional relational associations — frozen DEV protocol

Use only generated raw bytes and the consumed synthetic neural training fixture. For each seed 42, 43 and 44 generate four independent permutations over 16 entities, and train the repaired gated Monarch backbone using the existing longitudinal train function. Inputs expose an entity and one or two relation bytes before a single decisive outcome. The positions, entity alphabet, and operation of composing two edges are supplied to the structured arms. This tests acquisition of the edge values and reuse under an engineered grammar.

Expose the 64 primitive edges once in seeded shuffled order, then 64 of the 256 possible two-edge queries once in seeded shuffled order. The sum of zero-based entity and relation indices modulo four selects the repeated pairs (remainder zero). The other 192 composed prefixes are disjoint from exposure. Reset record context at every boundary for every arm. Score each exposure before updating it. After adaptation, freeze all arms, evaluate primitive recall, repeated-pair recall and unseen-pair first-target BPB and top-one accuracy separately. Start retention tracking immediately after each acquired record and probe every acquired record after every eight exposures. Store worst observed BPB drift per association. Synthetic DEV queries carry no protected first-use status.

Freeze five arms: the neural prior alone, sparse-support suffix memory, an exact full-prefix count lookup, a symbolic two-hop lookup of learned primitive edges, and a cue-conditioned local weight update. Give all arms the same exposure order. The local arm uses four 16-by-16 float32 matrices, one-hot primitive cues, soft intermediate activations, a local prediction-error step of 3, and a 1% neural prior at readout. The symbolic control joins primitive argmax edges with the same prior share. Structured controls receive the same grammar and entity alphabet. Sparse memory observes all transitions and makes its native posterior prediction. Bound adaptive state at 40,000 bytes per arm, excluding the common backbone and read-only evaluator data. Scalar count lookup is measured in compact JSON, local matrices as raw float32 and sparse memory via its versioned snapshot. No equal-compute, total-memory, or cold-restart claim.

The candidate passes only if unseen-pair first-target BPB beats the strongest of the four controls by at least 0.05 and maximum measured per-association drift is at most 0.02 BPB on each of the three seeds. Report all results, including ties and failures. No tuning or rerun based on outcomes. The executable generator, update rules, split and scoring are fixed in the same commit as this protocol before the workflow starts. No deployment or architecture-default change follows from a DEV result.
