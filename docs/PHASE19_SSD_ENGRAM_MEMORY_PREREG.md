# Phase 19 SSD Engram preregistration

Frozen development study on the `v1.3.0` base `fa8a42a35ca36d010842ed4aed49bae594cdb89a`. Run Linux CPU seeds 3301 through 3305 in order with one PyTorch thread and deterministic algorithms. All inputs are local. No donor models, external downloads, or online adaptation enter the comparison. The harness requires a clean direct child of the base and writes an intent binding the source commit, tree, and protocol digest before scoring. Preserve the raw result regardless of outcome.

## Data, model, and intervention

- Use Phase 17 `match_corpus` over the frozen repository prose/Python and synthetic arithmetic generator, including the train clipping to complete 32-byte target blocks and one starting byte. On a 32-byte overlap, test data-only candidate seeds `seed + 10000 × attempt` for attempts 0 through 7 and keep the first passing corpus. Record hashes, fixture provenance, and rejections. Recheck all FIT files against all CHECK files and require exactly zero shared 32-byte windows. Exhaustion invalidates the run.
- For each seed, train a mixed snapshot and two focused snapshots (`code`, `prose`) with the existing `train` CLI. Use the same initial seed, 32-wide two-layer native skill backbone, context 32, FP32 CPU, one epoch, 64 AdamW updates, and `--batch-per-domain 1`. Each update consumes three 32-byte target sequences, for 6,144 targets per arm. Use the default constant 0.003 rate and four development eval blocks in the training export. Use every CHECK target after the first byte in the scored comparisons. Freeze all neural weights and score the native neural next-byte softmax over at most the last 32 observed bytes, without the patch reader or existing online memory. Generation integrates the same Engram probability blend on top of its existing streaming forecast.
- Build one combined index from a directory containing only the three FIT files, and one index each for code FIT and prose FIT. Reset suffix history between source files. Retain every exact binary suffix of orders 4 to 12 with at least two observed successors. Store all sparse counts for each retained suffix. The SQLite file holds all counts and opens with a 2 MiB page-cache target and no mmap. Publish the exact file SHA-256 and verify it on each scored open.
- For a CHECK prediction, look up the longest matching suffix of previously observed bytes that has support of at least two. Use gate `0.35 × (order / 12)^4 × support / (support + 4)`. This downweights short contexts and small counts before seeing any result. Mix the base softmax with normalized successor counts in probability space and renormalize. A miss returns the input probabilities bit for bit. No gradient update, learned gate, domain hint, or future byte enters this intervention.
- Compare the mixed snapshot both with and without the combined index on math, code, and prose. Report BPB per domain and pooled as total negative log₂ probability divided by total predicted bytes. For the two out-of-domain pairs, score the focused prose snapshot with the code-only index on held prose, and the focused code snapshot with the prose-only index on held code. Keep each neural baseline fixed within its pair and report signed BPB delta and hit rate. The fixture measures interference on these pairs, with no assumption about unrelated streams in general.

## Engineering gate

- Zero shared 32-byte windows and zero donor forwards. The trained snapshots reproduce cold state and forecasts exactly and match the fixed update and target budgets.
- For each score, compare the full augmented forecast tensor and hit count from two independent SHA-pinned opens. Require `0.0` maximum difference and identical hit counts.
- Use the seed-3301 mixed snapshot and a separate index built from 12 repeats of a fixed 16-byte binary string. For seeds 0–99, sample an 8–16 byte prefix and append two independently sampled five-byte tails. Compare streaming forecasts and gain sequences after each observed byte against each other and against the truncated stream alone. Force the neural reader awake and disable adaptation. Require a positive Engram gain before the cut in every seed and `0.0` prefix differences throughout. The regression suite exercises the same check with its own local snapshot.
- Measure two fresh stdlib-only lookup processes against an index built from three repeats of seed 3319's 65,536 pseudorandom bytes. Run 4,096 12-byte queries per process, covering hits and misses by XORing the last four bytes on odd probes. Require identical result digests, both hits and misses in each process, at most **1.0 ms per lookup** and at most **64 MiB peak RSS** in either process. Record open-plus-hash time, build time, file size, and parent process peak RSS separately. This fixture measures bounded lookup memory at one index size. It leaves multi-GB build time, disk capacity, and live CUDA unverified.
- Require final bare `pytest -q` with zero failures, skips, and warnings, and legacy `benchmarks/prefix_causality_dev.py` at `0/100` failures. Git integrity and whitespace checks must pass before publication.

## Scientific DEV gate

- Benefit passes only if the Engram lowers pooled CHECK BPB in **5/5 seeds**. Interference passes only if the largest upward BPB difference across all ten out-of-domain pairs is **≤ 0.01**.
- Both arms passing yields **PASS**. Exactly one yields **MIXED**. Neither yields **FAIL**. A failed scored engineering gate makes the scientific comparison **INVALID**. Report actual per-domain and per-seed outcomes. The study uses repository text and synthetic math. It does not establish independent scientific qualification, broad collision avoidance, or generalization beyond these fixtures.
