# Static skill transfer: prospective method screen, donor swap and text challenge

Base d48b2df, isolated from the reported local Gates 30–32. This is a new DEV series, not a reproduction of those gates. Freeze this document, the runner and all choices before any scored execution. Branch dev/checkpoint-transfer-fidelity. Retain misses and censored times. Never select winners or tune parameters using confirmation or text test results.

## What is and is not being tested
Use the repository's dense trained donor and a tokenless DirectMonarch skill selected explicitly alongside a frozen Python-trained Nexus. Per-donor row permutations differ from the receiver's raw-byte order. Only the static tensors and singleton-byte vocabulary are supplied to conversion. Shared width 32, two compatible attention layers, matched position ranges, untied donor output head. This favorable interface isolates the nontrivial dense FFN conversion. Attention, norms and reindexed input/output tables are copied. Report total skill payload, including those shared parts. The int8 method evaluates a dense residual in the receiver; no free inference or arbitrary-model compression claim. No teacher-generated cache, no distillation, no donor inference during import, tuning or receiver verification.

## Frozen methods
Compare Gate 25 block rank-one fitting on four matrices with four corrections to the omitted weight matrix: another block-rank-one Monarch path, best global rank-four SVD, eight highest-energy Walsh input directions, and per-output symmetric int8 residuals with a scale. Each uses only weight algebra. Screen three seeds 101–103 by worst then mean zero-update donor-to-receiver full-distribution KL in bits, with serialized skill size then name as ties. Advance the top two. Always include scratch, parent-only and swapped-donor controls on the rule challenge. Hybrid checkpoints cross FFNs and complementary tensors while holding word identities fixed. A complete rank expansion is a mathematical ceiling, not a qualifying discovery.

## Data and selection
Each rule donor starts from the same seed's common dense Python-trained parent and sees one of two contradictory randomized mappings over eight entities and four cues. Each cue's donor B outputs derange donor A's outputs for every key. The receiver's scratch base is a separately trained Nexus on the same Python spans. On each trial all models see identical raw queries/labels, all 32 keys in balance, independently randomized filler bytes, and disjoint train/validation/test nonces. Evaluate fresh surfaces for acquired keys, not previously unseen keys. Screen only donor A per seed; fresh confirmation uses seeds 211–215, both donors and new rules. Compare their unadapted receivers on identical queries against both donors' targets. Training and isolated reference scoring by the *donor producer* are separately recorded; receipt probabilities are for blind evaluation only. Conversion cannot see these receipts, rules or targets. No paid APIs or external models.

Producer training stops at 100% validation accuracy and <=0.06 target BPB or 320 updates. A qualified rule donor needs >=95% test accuracy and <=0.20 test BPB. No dropping failed seeds. Near-lossless requires >=99% donor argmax agreement, KL <=0.02 bits/target, target BPB <= donor +0.02 and >=95% task accuracy on every qualified donor, plus all ten donors qualified for a full pass. Swap specificity requires correct-rule accuracy minus opposite-rule accuracy >=0.90 in both directions on each seed. Old-mode raw predictions must remain byte-identical. Report zero-update and after-tuning outcomes separately.

Common receiver stop is first validation checkpoint with >=95% accuracy and <=0.20 target BPB. Check at zero then every eight updates through 160. Lock stopping using validation and score the selected state once on test; a validation crossing only counts as a matched-quality success if the absolute target holds on test too. Two timing repetitions per confirmation arm, same initial state, shuffled arm order per donor, one CPU thread, median measured inclusive time (model/skill construction, disk load, conversion, tuning and validation). Time receiver operations end-to-end, excluding common data/base production and independent auditing. Report donor production separately; for an already existing checkpoint it is sunk cost. Compare with scratch reaching the same target. A non-crossing baseline is censored; never invent an exact saving. Seek >=25% time reduction on every paired eligible case. Wrong donor and parent are separate warm-start controls. Run hybrid FFN-versus-rest transplant before tuning for attribution.

## Natural-text follow-up and stopping
Lock the highest-ranked screen winner plus block-rank-one baseline, scratch, and a wrong-domain common parent on two disjoint repo Markdown file groups and five fresh seeds 311–315. Train on the first set, use a separate file for stopping and a fourth for test. Freeze paths, offsets, processed hashes and overlap exclusions as specified by the runner. No cross-window transitions. Challenge the entire 256-way next-byte distribution; this is independently initialized DEV within a previously seen repository. Stop on validation BPB <= donor validation BPB+0.02; compare at zero and at the stop. Same 160-update ceiling. Require per seed >=99% reference agreement, <=0.02 bits KL and target BPB <= donor+0.02. Test equality of old-mode logits. Report conversions and total receiver time, including every validation evaluation. Follow-up times for text use one observation per arm. Timing results apply to the measured host and budget.

If the selected winner misses either confirmation fidelity or text fidelity, automatically evaluate the prespecified residual16 method on fresh rule twins and text (seeds offset +1000, same protocol). This last method stores an FP16 dense residual on top of a Monarch fit, a higher-storage engineering fallback. Compare with scratch, parent and donor swap. End this series once qualifying near-losslessness is found or this frozen ladder is exhausted; publish the outstanding failure and next discriminating test. No inference about multi-byte vocabularies, unrelated widths, open-domain competence, or the user's local Gates 27–32.
