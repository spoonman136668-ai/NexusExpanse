# Gate 4B frozen real-corpus streaming DEV protocol

Fix all bytes to Git commit 52db0107dfb3ea98c581509af3422594148864b9. Train on Python package source and evaluate on Markdown prose from other files. These are different file domains in one familiar repository, not independent authors or a protected corpus. GATE4B_MANIFEST.json fixes full-file and span SHA-256, offsets, lengths, rejected windows and ordering. gate4_corpus.py reconstructs and compares the complete manifest before scoring. Reject duplicate whole files. Scan aligned 256-byte windows in path order, accepting up to four per training file and two per evaluation file. Reject any candidate sharing a 32-byte substring or a lowercased five-word-shingle Jaccard similarity of at least 0.35 with an accepted span. File tails shorter than 256 bytes are ineligible. 31 train and 8 DEV spans, no cross-span transitions. No labels, tokenizer or held-out first use.

Train one gated backbone per architecture and seed (42–44), two epochs, equal steps and byte order, shared initial non-FFN tensors, AdamW lr .003, weight decay .01, gradient clip 1, auxiliary coefficient .1, between-epoch train-only calibration. At evaluation, clone the exact trained checkpoint for always-on, causal FFN skip, and dynamic patch inference and verify the trained tensor hash for every clone. This isolates deployment-policy differences conditional on joint gated training. Compare with static and online bounded memory alone, once each because deterministic. Initialize all memories from identical training observations; use sparse support, max order 8, serialized ceiling 40,000 bytes. Reset context at span boundaries and carry learned state between spans.

The patch predictor is a train-only add-one byte bigram. Wake deep attention on the first observed byte or whenever that already-observed byte had more than 4 bits of local surprise. Between events forecast with the bigram and fold each low-surprise run to its final raw byte. At the next wake retain that byte and the event byte in a 32-byte deque. The always-on and FFN-skip streaming comparators re-evaluate the available rolling 32 raw bytes at every transition. No KV cache or optimized batched scoring. All neural arms use the same one-bin fixed-share neural/memory arbitrator. Frozen probes disable all learned-state writes (initial mixer share .5). Prequential probes score first, then update memory and mixer, beginning from the same training state. The patch observer tracks read context in both modes.

Measure FP64 target log losses (floor 1e-300), per-span and pooled BPB. Record measured streaming wall ms per scored byte including arbitration and writes, separate fresh-process end-to-end ms per byte including startup/manifest verification/loading, Linux process high-water RSS in decimal MB, full neural parameter+buffer bytes, serialized neural checkpoint plus full inference-state byte components, and maximum serialized episodic state. Raw continuation bytes are counted separately; canonical code/configuration, interpreter and Python object overhead are outside serialized-state totals but included in process RSS. Derived local row totals need no serialization and are reported separately. No throughput inference from call counts. Each policy/mode gets a fresh single-thread process, one timed pass in fixed order, shared CPU runner. Report training seconds separately; DEV timing has no repetition-based uncertainty or hardware generality.

Record outcomes without tuning. Qualify a patch advantage for a given architecture only if on every seed in both modes it is at least 10% faster in streaming ms/byte and within +0.02 BPB of **each** always-on and causal-skip comparator. Also report whether it beats the memory-only control on quality and time. Keep both modes, both architectures, state and RSS costs regardless of decision. No deployment promotion.
